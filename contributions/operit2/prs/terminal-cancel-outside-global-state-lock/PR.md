## 变更说明

### 问题

一个会话进入超时取消等待时，会占有整个 Android 终端状态互斥锁，最长覆盖现有 3 秒恢复窗口；其他会话的读取、输入、列表与关闭操作也因此停顿。

### 原因

原调用方在 `self.lockState()` 的 guard 内，把可变 session 交给取消函数。该函数等待输出条件变量直至恢复提示符或取消截止时间，导致整个状态锁随等待持续持有。

### 修复

取消函数改为只接收现有 writer 与 commandOutput 的共享句柄。调用方在获取结果后、重新锁定状态之前执行 Ctrl-C 和等待，最后仅持状态锁更新目录及运行标志。

取消写入移出 state 锁后，close 可以与写入并发；因此附带已有写端 fd 所有权修复作为必要前提。单次 syscall 持有 fd 锁并检查关闭标记，master 使用 nonblocking，短写/瞬时错误在释放锁后重试，连续 5 秒无进展时返回错误。这些配套代码亦包含于 `terminal-descriptor-lifetime`，在这里重复以保证本 PR 可独立应用；没有加入旧 reader 生命周期修复。

## 影响范围

- 平台：Android。
- 模块：`hosts/android/src/terminal.rs`。
- 行为：不同会话和终端管理操作不再被某个会话的取消恢复等待整体阻塞。仍使用既有 Ctrl-C 行为和 3 秒取消窗口；session 在等待期间已被关闭时，状态更新延续原有不存在即跳过的处理。
- 兼容性：复用现有 Android host API；不修改 Rust runtime 与 Flutter 的接口边界，无配置、数据库或数据迁移。
