## 变更说明

### 问题

两个并发请求首次创建同名终端或同一隐藏执行器时，都可能看到映射为空并分别启动 PTY，返回不同会话并覆盖名称映射。

### 复现步骤

1. 从两个线程同时使用同一个 sessionName 创建命名终端；对 executorKey 重复同样场景。
2. 让两个请求同时通过已有映射检查后再完成 PTY 初始化。
3. 观察两次创建得到不同 sessionId，映射只保留最后一次写入。

以上是根据现有控制流整理的复现路径，本次未在 Android 设备上执行。

### 原因

现有 state mutex 分别保护查询和插入，中间启动 PTY 时释放锁，因此整个查找/创建/登记过程不是原子操作。

### 修复

在 host 中添加可被克隆实例共享的 sessionCreation mutex，覆盖可见和隐藏两条命名创建流程；继续使用原有 state mutex 保护短暂 map 操作。
